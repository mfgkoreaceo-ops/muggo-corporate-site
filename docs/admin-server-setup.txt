MUGGO 실제 관리자 로그인/게시 서버 연결 절차

현재 상태
- GitHub Pages는 정적 사이트입니다. /auth/github를 구현하지 않으므로 해당 주소로 이동해도 로그인할 수 없습니다.
- Pages의 로그인 링크는 동일 출처 /api/capabilities에서 서버 구성이 확인된 경우에만 노출합니다.
- Render 연결, 유료 리소스 생성, GitHub App 등록/키 생성은 이 코드 변경만으로 실행되지 않습니다.
- deploy/render.yaml은 수동 검토/적용용입니다. Starter 서비스 1개와 1GB 디스크가 포함되므로 비용 승인 없이 적용하지 마세요.

1. Render 준비
기존 계정을 연결하고 기존 서비스를 재사용할 수 있는지 확인합니다.
새 서버를 승인한 경우 이 저장소 main을 사용하는 Node 24 Web Service를 생성합니다.
Build Command: npm run check
Start Command: npm start
Health Check Path: /healthz
HOST: 0.0.0.0
GITHUB_AUTH_MODE: github-app
CMS_STATE_DIRECTORY: /var/data/muggo
CMS_BRANCH: main
CMS_PUBLISH_ENABLED: false
Persistent Disk: /var/data/muggo 에 1GB, 인스턴스는 1개.
Render가 제공하는 RENDER_EXTERNAL_URL과 RENDER_GIT_COMMIT을 서버가 사용합니다.
커스텀 도메인 사용 시 ADMIN_ORIGIN에 정확한 HTTPS 출처(마지막 / 없음)를 별도 지정합니다.
이 단계의 실제 게시 기능은 계속 비활성화합니다.

2. MUGGO 전용 GitHub App 등록 (기존 ChatGPT Codex Connector와 별개)
사용자가 앱 등록과 권한 승인을 진행합니다. 새 키/비밀값을 채팅이나 저장소에 넣지 않습니다.
공식 등록 안내: https://docs.github.com/en/apps/creating-github-apps/registering-a-github-app/registering-a-github-app
앱 이름: 계정 내 고유한 MUGGO 관리자용 이름
Homepage URL: 실제 Render 관리자 HTTPS 주소
Callback URL: 같은 주소의 /auth/callback
Repository permissions: Contents Read and write, Metadata Read-only.
향후 배포 상태 조회를 구현할 경우 Actions Read-only가 추가로 필요할 수 있으나, 현재 로그인/커밋에 필수로 요청하지 않습니다.
현재 웹훅 처리는 구현하지 않았으므로 웹훅은 비활성으로 등록합니다.
사용자 액세스 토큰 만료 기능은 유지합니다. 개인 계정에서만 쓸 앱이면 Only on this account를 선택합니다.
만든 앱을 mfgkoreaceo-ops 계정에 설치하되 muggo-corporate-site 저장소만 선택합니다.
사용자 OAuth 흐름을 사용하므로 이 코드에는 개인 키 파일을 업로드하지 않습니다.

3. 서버 환경 변수 입력
GITHUB_CLIENT_ID: 새 MUGGO GitHub App의 Client ID (App ID와 다름)
GITHUB_CLIENT_SECRET: 새 앱의 Client secret — 사용자가 Render 비밀 환경 변수에 직접 입력
GITHUB_APP_INSTALLATION_ID: 새 MUGGO 앱의 설치 설정 주소 끝 숫자
  예: https://github.com/settings/installations/<숫자> 의 숫자. Codex Connector 설치 ID를 대신 사용하지 않습니다.
CMS_GITHUB_USER_ROLES: 허용 사용자 숫자 ID를 역할로 연결하는 JSON
  현재 저장소 소유자 mfgkoreaceo-ops의 숫자 ID는 265666658입니다.
  이 계정만 최고 관리자로 승인하는 경우 {"265666658":"super_admin"}
  사용자를 더 승인하려면 해당 사용자의 실제 숫자 ID를 확인한 뒤 추가합니다.
서버는 ID 허용 목록뿐 아니라 사용자 토큰이 지정 설치의 MUGGO 저장소에 접근 가능한지도 확인합니다.
직원에게 서버 권한을 준다고 GitHub 저장소 쓰기 권한이 생기지는 않습니다. 게시 시 GitHub 쓰기 권한도 별도 검증합니다.

4. 실제 로그인 검증
Render의 /healthz → 200, /api/capabilities → loginAvailable=true, publishEnabled=false 확인.
그 Render 주소의 /admin/ 접속 → GitHub 로그인 → 승인한 사용자 계정 인증.
반드시 최종 주소가 Render /admin/이고 관리자 화면이 자동으로 열리는지 확인.
서버 세션 복원, 로그아웃, 만료, 미승인 사용자 차단도 검증합니다.
Pages 주소에서는 서버 로그인이 제공되지 않습니다. 직원은 새 관리자 주소를 사용해야 합니다.
기존 직원 초안은 Pages 출처에서 백업한 후 새 관리자 주소에서 콘텐츠만 복원합니다.

5. 실제 게시 활성화 전
기존 운영 채용 데이터로 시험하지 않습니다. 격리된 테스트 저장소를 대상으로 실제 인증/쓰기/충돌을 검증해야 합니다.
현재 서버는 MUGGO 저장소를 고정 사용합니다. 테스트용 배포에서는 테스트 저장소를 지정한 별도 검토 브랜치를 사용해야 하며,
테스트 중 임의의 저장소 경로를 클라이언트가 전달하도록 바꾸지 않습니다.
실서비스를 게시 대상으로 바꾼 최종 코드, 권한, diff, 테스트 결과를 다시 검토받은 후 CMS_PUBLISH_ENABLED=true로 설정합니다.
커밋 생성과 Pages 배포 완료는 별개입니다. 원격 커밋/파일 검증 후 GitHub Pages 배포와 공개 화면도 확인해야 합니다.

예상 비용
이전에 확인한 신규 Render 기준 서버 약 $7/월 + 1GB 디스크 $0.25/월부터. 세금/초과 사용량은 별도.
https://render.com/pricing 의 생성 시점 가격과 기존 계정 청구 조건을 확인한 뒤 사용자 승인을 받습니다.
기존 서버 재사용 시 추가 비용이 달라질 수 있습니다.

테스트 범위
자동 테스트는 로컬 HTTP와 모의 GitHub API 흐름입니다. 실제 서비스의 GitHub 사용자 동의/쿠키/권한/게시 성공 증거가 아닙니다.
한 프로세스/한 인스턴스로 운영해야 합니다. 세션은 메모리에 보관되어 서버 재시작 시 재로그인이 필요합니다.
